# M2: USB commands

Status: initial hardware runs on 2026-11-15 established state readback and gain switching while ffmpeg streams through standalone Terminal on macOS. Manual NUC and temperature calibration remain unresolved. [Protocol and confidence](../protocol.md) records what can be attempted, and why NUC is unavailable.

## Run

Use Node 26+, `npm ci`, and ffmpeg on PATH (or `IRVIS_FFMPEG`). Keep the camera aimed at a static scene, including room-temperature and warm objects. Save each log under a new name: `--out` refuses to overwrite.

```sh
mkdir -p captures/m2
npm run spike:m2 -- list --out captures/m2/devices.jsonl
npm run spike:m2 -- state --out captures/m2/initial.jsonl
npm run spike:m2 -- gain low --video 0 --out captures/m2/low.jsonl
npm run spike:m2 -- gain high --video 0 --out captures/m2/high.jsonl
npm run spike:m2 -- watch --video 0 --seconds 60 --out captures/m2/watch.jsonl
npm run spike:m2 -- state --video 0 --seconds 60 --out captures/m2/baseline.jsonl
npm run spike:m2 -- nuc --out captures/m2/nuc.jsonl
```

Replace `0` with the macOS AVFoundation camera index from `npm run capture -- list`; on Linux use `/dev/videoN`. `--device <bus>:<address>` selects USB separately using the address from `usb list`. USB selection and video selection must name the same physical camera. Do not run two USB command processes at once. `--video` starts ffmpeg four seconds before reading state and issuing the command, then keeps it running for `--seconds` (default 12) after state readback. Without `--video` the tool also works while another process captures video.

`watch` reads all state, including experimental `cur_vtemp`, about once per second, without overlapping transactions. Errors can make intervals longer. Compare with `state --video`, which streams without periodic USB reads. Each frame logs arrival interval, late arrivals (>60 ms), upper-byte mean, lower-half raw min/max/mean and change flags. `rawStep` means a mean change greater than 32 raw units, `upperStep` greater than two byte units. These are heuristics; motion, palettes, pipe buffering and automatic NUC can cause them. They do not prove dropped frames or a gain switch. ffmpeg uses passthrough timing rather than filling timestamp gaps with duplicates. The probe rejects a stream with no complete frame for more than two seconds when it checks startup, before the command or in the observation loop. Arrival times are pipe receipt times, not camera capture timestamps. Use the M1 capture/report for packet timing, NUC events and saved frames when needed.

For TPD experiments, first save `state`, then run `tpd ems 100 --video ...` and `tpd tu 310 --video ...` separately. Restore each original raw value using `tpd <name> <raw>` before the next experiment; the tool does not restore automatically. Compare lower-half statistics with the baseline: changes would mean software must account for camera-applied corrections. Test `palette 3 --video ...`, then restore the original palette (hex in the state log). A lower-half change would invalidate the assumption that palette affects only the image.

Record low/high raw values for the same stable reference targets, together with independently measured temperatures. One scene without reference temperatures cannot identify a trustworthy low-gain conversion. Watch gain readback for automatic switching; raw change flags alone cannot identify it. After settings experiments, unplug, replug, rerun `list` (the address may change) and `state`, and compare every TPD field and palette with the pre-unplug snapshot.

Ctrl+C (SIGINT) or SIGTERM cancels the session, stops its ffmpeg, attempts reattachment of a detached driver and closes USB before exiting (130 or 143 respectively). In-flight transfers finish or time out before cleanup; no new transfers or post-command state reads are started after cancellation. SIGKILL cannot run cleanup.

## Platform attempts

- (a) Default EP0 path, first without streaming and then with `--video`. Preserve errors and transfer logs.
- (b) Stop ffmpeg and all camera apps. Run `npm run spike:m2 -- state --detach --out captures/m2/detach.jsonl`. Do not use this to claim the released app can stream and control simultaneously. Record whether permissions/root were required; do not run the whole spike as root by default.
- (c) If (a) fails, build and try the IOKit helper below, with and without `--video`. It never seizes or detaches the device. Preserve its exit status and IOKit error codes. The [local hardware run](#local-hardware-run) records successful IOKit state reads during streaming on one T7; repeat this test for the target environment.

```sh
clang -framework IOKit -framework CoreFoundation tools/capture-cli/iokit-request.c -o .context/iokit-request
npm run spike:m2 -- state --iokit .context/iokit-request --video 0 --out captures/m2/iokit.jsonl
```

On Linux, install `tools/capture-cli/60-irvis.rules` as `/etc/udev/rules.d/60-irvis.rules`, run `sudo udevadm control --reload-rules`, then reconnect the camera as an active local desktop user. Run the same sequence with `--video /dev/videoN`. The rule grants uaccess for both profile PIDs and does not unbind UVC. Headless sessions may need administrator-managed permissions instead.

## Local hardware run

Environment: TOOLTOP T7, USB `0bda:5840`, macOS 27.0.1 (26A434), arm64, Node 26.11.1, ffmpeg 9.0.2. Logs and frames are local under `.context/m2-hardware/`; no image data are committed.

The initial connected-camera run exposed two integration errors that transport mocks had missed: installed `usb` 3.3.0 has no legacy `getDeviceList` export, and the 2.x OUT callback returns a byte count rather than a Buffer. The tool now uses `usb` 2.19.1, the M1 probe creates an explicitly authorized `WebUSB` instance, and logging handles numeric OUT results. A hardware-free integration test imports the actual dependency to guard its API shape.

Direct Conductor-launched ffmpeg produced no frames. TCC logs attributed access to `com.conductor.app` and reported a missing camera entitlement, without displaying a permission prompt. A script sent by AppleScript to Terminal was also attributed to Conductor in this run. After finding the successful M1 `.command` script in the `worcester` workspace, launching a local executable `.command` with `open -n -a Terminal <absolute-script-path>` produced 76 packed frames in a three-second capture, first frame after 2321 ms. The terminal must already have camera permission or the owner must grant the system prompt. No permissions or entitlements were modified by the tool.

Initial state and readback after reconnect: distance 32, TU 300, TA 300, EMS 128, TAU 128, gain 1, palette `01`. Sensor-temperature bytes changed from `23ed` to `0000` across reconnect and remain uninterpreted. Reconnection preserved these initial settings, but that does not prove persistence of deliberately changed settings. The EMS/TAU values contradict the upstream stated maximum 127; the probe now allows restoring raw 128 without assuming a ratio divisor.

Without a video stream, gain readback changed `1 → 0 → 1`; high gain was restored. Both legacy EP0 and the IOKit helper read all state without claiming or detaching an interface. Kernel-driver queries reported both interfaces active. Detach was unnecessary for the successful default path and was not attempted; Linux remains untested.

Streaming experiments and limitations are recorded below. These are observations of an uncontrolled scene, not calibrated measurements. The early frames after opening the camera contained transient values near 32768; differences between pre-command and post-command aggregates can therefore include camera startup. Arrival FPS also includes pipe buffering and is not a camera-rate measurement.

All nine short streaming commands exited 0. Gain readback changed `1 → 0 → 1`, palette `01 → 03 → 01`, and TU `300 → 310 → 300`; all were restored. Each run kept video open during its USB operations and observed eight seconds after the command. The watch run read full state (including sensor bytes) approximately once per second. The IOKit run also read state while video continued.

The scene was not independently temperature-referenced; low-gain calibration and automatic-gain detection remain open. Manual NUC is still unsupported and no audible shutter observation is claimed.

### Continuous capture

A subsequent 70-second capture kept ffmpeg open across all commands, waiting 12 seconds before the first state snapshot. It saved **1751 frames**, all packed as `yuyv422`, with zero trailing bytes. Source PTS gave 25.0022 fps, a maximum gap of 40.034 ms and zero inferred missing frames (rounded intervals at 25 Hz). This establishes successful control/video coexistence for this local run, not for other machines or platforms.

The table averages frames from two seconds after each state readback until the next command. Raw mean SD is temporal variation of the whole-frame mean, not NETD. Times align the JSONL wall clock with capture arrival times; the scene was uncontrolled.

| `low` | 158 | 17862.262 | 46.142 | 119.056 |

| `ems128` | 82 | 18974.844 | 2.911 | 85.635 |

Gain readback and the raw range changed together, and returning to high gain returned the mean near its initial level. This does not identify a calibrated low-gain divisor. Palette and EMS writes also completed and read back, but scene drift, automatic shutter activity and the uncontrolled target prevent attributing every thermal change to the setting. In particular, the palette experiment does not prove that only the upper half changes, and the EMS/TU trials do not settle whether software correction would double-apply emissivity.

The final snapshot confirmed distance 32, TU 300, TA 300, EMS 128, TAU 128, gain 1, palette `01`. Initial configuration was restored; sensor-temperature bytes remained raw observations. Changed-setting persistence after unplug, a reference-temperature low-gain fit, manual NUC and Linux measurements remain open. No kernel driver was detached.

### Descriptor probe follow-up

On 2026-11-15, the M1 USB descriptor probe was rerun after replacing the unauthorized WebUSB singleton with an instance configured for the profile's IDs. It found `0bda:5840`, decoded configuration 1 and extension unit 4 (`1229a78c-47b4-4094-b0ce-db07386fb938`, two controls), and reported 256×192 and 256×384 uncompressed modes at 25 fps. Automatic driver detachment was disabled; no camera setting was changed. Local output: `.context/review-3-fixed-probe.txt`.
